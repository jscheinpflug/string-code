#+title: Tensor-Only Production Readiness Handoff
#+auto_tangle: nil

This handoff records the tensor-only production gate, the closed acceptance
items, and the remaining future boundaries after the first production cut.  It
is a continuation of
[[id:20260613T120000.000000][Performant Tensor-Only Solver Plan]],
[[id:20260610T235000.000000][General Tensor Product Brauer Solver Handoff]],
[[id:20260610T191000.000000][Tensor-Only Scale Audit Benchmark]], and the live
implementation in [[id:20260608T001501.000000][Projector Constructor]] and
[[id:20260606T211001.000000][Tensor Context]].

The target is a production solver for non-spinor orthogonal \(B/D\) tensor
irreps.  Spinor and tensor-spinor channels may continue to use the Clifford
route, but the tensor route must be independent, stream-shaped, budgeted, and
usable from the public context API.

tensor-only route exists:

  -> tensor-only endpoint/channel
  -> endpoint projectors
  -> raw Brauer diagram stream
  -> projected endpoint action stream

  -> paged primitive atom stream

The solver has moved through the acceptance checklist for the tensor-only
non-spinor target.  The remaining release work is final validation and keeping
future expansion boundaries explicit.  Tensor-spinor joining, wider
trace-removal cleanup, and broader family universality are not hidden fallback
work for this gate; they are separate future scopes.

* Production Definition

The solver is production-ready when all of the following are true:

1. A caller can register any supported non-spinor \(B/D\) tensor irreps, request
   an invariant basis or product channel, and stream expanded independent
   invariants without naming representation-specific formulas.
2. The implementation path is the general tensor path for supported endpoints:
   descriptor lowering, endpoint projector construction, Brauer action,
   canonicalization, sparse Gram pivots, and primitive atom rendering.  It must
   not rely on vector-only fixtures or per-representation formula tables.
3. Every mathematically supported tensor-only request either streams terms or
   fails by an explicit resource budget.  It must not become
   =ProjectorExpansionNotImplemented= because an old helper had a compact
   fixture cap.
4. The live path never materializes a full large expression.  It counts, audits,
   pages, and streams with bounded memory.
5. Every hard implementation cap is documented as either:
   - a deliberate public resource policy field,
   - a small scratch chunk with chunked continuation,
   - or a known unsupported algebraic case.
6. Scale benchmarks cover mixed Young shapes, products, Hodge endpoints, large
   row lengths, many factors, and failure under tight budgets.
7. Output is primitive tensor algebra: rational coefficients, deltas, metrics,
   form slot maps, Hodge or epsilon atoms.  No placeholder projector, Young, or
   trace-free atoms may appear in expanded tensor-only output.

* Supported Target

The production target is:

#+begin_src text :tangle no
B_r / D_r non-spinor tensor irreps
ordinary Young tensor shapes
exterior form shapes
middle-rank self/anti-self-dual forms
products of such endpoints
scalar invariant channels and non-scalar structural output channels
#+end_src

Here "supported families" means all tensor-only endpoint families in that
non-spinor \(B/D\) target: Young, exterior, Hodge, mixed tensor/form where
lowered structurally, and products of those endpoints.  It does not mean
spinor or tensor-spinor endpoints through the tensor-only solver.

Out of target unless explicitly joined later:

#+begin_src text :tangle no
spinor irreps as tensor-only endpoints
tensor-spinor irreps as tensor-only endpoints
Clifford/gamma routes
exceptional and A/C family tensor-only universality
symbolic closed-form product decomposition for every Lie type
unbounded computation with no caller resource policy
#+end_src

Spinor and tensor-spinor paths should remain working, but they are not the
criterion for shipping the tensor-only solver.  Their current route remains the
separate Clifford/gamma path until a future tensor-spinor join is explicitly
designed and audited.

** P0.1 Algebraic Coverage Audit

Before further widening work, write down and check the actual mathematical
route for every supported endpoint class.  This is the proof spine of the
solver, not a test matrix.

Current audit artifact:

#+begin_src text :tangle no
[[id:20260614T230000.000000][Tensor-Only Algebraic Coverage Audit]]
#+end_src

The audit records the intended singular route, classifies Young, exterior,
Hodge, mixed, and product endpoints, and separates exact special cursors from
legacy compatibility fallbacks.  It also lists the remaining fixed ceilings.
The constructor exposes =tensorOnlyCapAudit= as code-level cap output, and
=Context= exposes the same audit for the active tensor-only policy.  Public
product-routing gaps are closed for supported tensor-only endpoints by shifted
factor projectors, exact factor scalar cursors, or generic Brauer streams.

Required work:

#+begin_src text :tangle no
classify supported B/D non-spinor endpoints as Young, form, Hodge, or product
state the endpoint projector construction used for each class
state the invariant bilinear form / contraction oracle for each class
state how Hodge constraints enter the endpoint projector and render atoms
state how tensor products compose endpoint actions without decomposing by tables
state why sparse Gram pivots give independent invariants after projection
identify every place where trace removal, symmetrization, antisymmetrization,
  and Hodge projection can still fall through a vector-only helper
#+end_src

Acceptance criteria:

#+begin_src text :tangle no
there is one explicit route from descriptor to primitive atoms for each endpoint class
no supported class depends on a hand-written product formula table
Hodge and multi-Hodge products have a stated exact algebraic path
remaining unknowns are tagged as unsupported mathematics, not implementation gaps
#+end_src

** P0.2 End-To-End Arbitrary Tensor Product Path

The constructor can solve many general tensor channels, but public invariant
generation still depends on coupling paths and local projector derivations.  We
need arbitrary registered tensor products to route through the tensor-only
solver wherever the endpoints are tensor descriptors.

Required work:

#+begin_src text :tangle no

audit localProductProjectorDerivation for every B/D tensor descriptor kind
ensure multiplicity handling never masks a tensor-only route
route product endpoints through structural specs without legacy shape fixtures
remove any public fallback that emits named projectors for supported tensor paths
make missing decomposition distinct from missing tensor projector construction
verify scalar invariant and non-scalar structural channels use the same engine
#+end_src

Acceptance criteria:

#+begin_src text :tangle no
vector x vector -> scalar/form/symmetric uses the tensor-only engine where applicable
form x form -> scalar/Young/form/Hodge uses the tensor-only engine where applicable
Young x Young -> Young/scalar uses the tensor-only engine where applicable
Hodge x Hodge and mixed Hodge products use exact endpoint constraints
product endpoints with 6-12 factors compile or budget-fail
all supported failures are resource-policy failures, not formula gaps
#+end_src

** P0.3 Streaming Sparse Solver Path

Production performance depends on never building the expanded object unless the
caller asks for a bounded page.  The solver must treat diagrams, endpoint
actions, candidates, pivots, and rendered atoms as streams or compact sparse
buffers.

Required work:

#+begin_src text :tangle no
keep raw Brauer diagrams behind a cursor, not an owned full list
apply endpoint projectors into sparse action words with bounded scratch storage
canonicalize candidates incrementally and deduplicate by compact keys
build sparse Gram rows lazily and pivot without dense matrices
render primitive atoms by page from the solved basis
make filters skip rejected terms without materializing them
carry first_term and max_terms through Context to constructor page APIs
#+end_src

Acceptance criteria:

#+begin_src text :tangle no
large expanded symbolic expressions are never allocated before paging
page 0 and page 1 concatenate to the same stream as full rendering
page beyond term_count returns zero emitted terms after bounded work
peak live memory scales with sparse row/page width, not total expression size
#+end_src

#+begin_src text :tangle no

legacy u8 vector-backed path is not chosen for wide tensor-only channels

#+end_src

** P1.1 Benchmark Matrix

Create a focused benchmark matrix in or near
[[id:20260610T191000.000000][Tensor-Only Scale Audit Benchmark]].  Do not run broad
tests constantly during development; run this matrix before release.

Minimum cases:

#+begin_src text :tangle no
D5 vector^4 -> scalar
D5 two_form x two_form -> scalar
D5 two_form x two_form -> Weyl
D5 hook x symmetric^2 -> middle Hodge form, budgeted when the raw Brauer
  boundary is too large for the release matrix
D5 hook x symmetric -> vector
D5 product of 8 vectors -> scalar
D5 product of mixed forms with Hodge factors -> scalar
D8 product of 10 vector/form factors -> scalar
D12 ten-row Young descriptor route -> budgeted count/audit
wide symmetric row 300 x vector -> row 301 route
tight raw_diagram_count_limit -> TensorResourceBudgetExceeded
tight output_term_page_limit -> partial page and audit
#+end_src

Current status: the broad =large=, =solve-large=, and =render-large= audit
matrix completes.  The D5 hook/symmetric-to-Hodge stress row budget-fails by
resource policy instead of entering unbounded pre-pivot work.  The D5
one-sided vector-product scalar row now audits through the streamed pairing
cursor in scale, solve, and render modes.  The mixed Hodge product and D8
ten-factor vector/form product rows are now broad release-matrix rows and
budget-fail by resource policy in scale, solve, and render modes.

The one-sided vector-product scalar stream is structural, not a =D5= or
=vector8= fixture.  It is exercised across different dimensions, factor
counts, and product sides, and its page emitter reuses pairing buffers across a
page instead of allocating per emitted term.

Record for each case:

#+begin_src text :tangle no
term count
raw diagram count
candidate count
pivot count
max sparse row width
max coefficient bits
first page latency
process RSS before/after/delta and VmHWM
peak allocator footprint remains future work unless an allocator-threaded route is used
error under tight policy
#+end_src

Current benchmark rows now print =rss_before_kb=, =rss_after_kb=,
=rss_delta_kb=, and =vmhwm_kb= for scale, solve, and render modes.  These are
process-level memory counters from =/proc=, not exact owned allocator bytes,
but they give the release matrix a comparable memory signal for success and
budget-failure rows.

The public =Context.renderInvariantFiltered(... expanded_terms ...)= path now
uses the same policy-scoped structural cache term counts as the direct
count/page surface.  A budgeted Spin10 two-form times symmetric-tensor channel
is covered by a regression that previously emitted 324 terms despite
=output_term_count_limit = 0= and now stops with
=TensorResourceBudgetExceeded= before emitting.

** P2.2 Wide Trace-Removal Rank

Several trace-removal/idempotent routines still use compact rank types.  The

Work:

* Completed Implementation Order

1. Complete the algebraic coverage audit for Young, form, Hodge, and product
   endpoints.
2. Force all supported B/D non-spinor tensor products through descriptor
   lowering and the tensor-only engine; remove table/formula fallthroughs.
3. Finish the stream/sparse execution path from Brauer cursor to paged primitive
   atoms, with no full-expression allocation.
4. Audit every remaining =ProjectorExpansionNotImplemented= in expanded tensor
   rendering and convert supported tensor cases to tensor-only or resource
   limits.
5. Add benchmark matrix cases and record baseline counts, sparse widths,
   coefficient growth, first-page latency, and memory.
6. Convert row_count > 32 from a descriptor cap into span-backed metadata, or
   explicitly declare 32 rows as the first production limit.
7. Remove the live-path dependence on compact vector-backed =u8= rank APIs for
   wide tensor-only endpoint projectors.
8. Add the minimal public count/audit/page surface in =Context= for bounded
   production runs.
9. Run release validation and keep failure classification minimal.
