#+title: CFT DSL Unification Implementation Plan
#+auto_tangle: nil

This plan turns the current mixed CFT implementation into a single-source DSL
pipeline:

#+begin_example
Lisp worldsheet DSL
  -> validated descriptor data
  -> Zig comptime lowering
  -> correlator, basis, zero-mode, infinity, and ABI programs
#+end_example

The goal is that adding a new free-field worldsheet theory normally means
writing only the DSL declaration.  We should not write a new handwritten Zig
preset, a new ABI switch arm, a new basis generator, and a new field-inserter
module for each theory.  The DSL must carry enough data for Zig to compute the
static programs at compile time.

This plan responds to the audit in =cft-audit.org= and the response in the root
file =cft-audit-response.org=.

* Design Principles

1. The user writes worldsheet physics, not plumbing.

   A theory declaration should name fields, weights, statistics, labels,
   surfaces, Wick kernels, zero-mode measures, basis behavior, infinity
   behavior, and boundary extensions.  The DSL should derive conventional data
   when it is unambiguous, and require explicit data when it is not.

2. Lisp macros should do real compile-time work.

   =define-cft-preset= should parse, validate, derive defaults, assign stable
   names, generate runtime inserters, and export the public interface at macro
   expansion time.  Runtime builders should remain available for tests and
   REPL experiments, but the normal development path should fail early with
   source locations.

3. Zig receives compact data and computes static programs.

   The Zig side should not know about "free boson", "bc", "eta-xi", or "free
   fermion" as special cases in the core generated path.  It should lower
   descriptor records into:

   - Wick pair programs.
   - Infinity descendant programs.
   - Basis oscillator and seed programs.
   - Zero-mode measure programs.
   - ABI dispatch tables.

4. Zero modes are declarative measures, not a short list of presets.

   The current =constant_fermion=, =top_form_fermion=, and momentum-conservation
   cases are examples of residual measures.  The replacement should describe
   how residual fields are selected, saturated, transformed, and emitted.  It
   should not force every new worldsheet zero-mode rule into a hardcoded enum
   arm.

5. Keep data-oriented, bounded execution.

   Runtime should stream over precomputed arrays with stack-bounded scratch.  No
   symbolic expression trees, no heap allocation in the Wick walk, and no
   theory-specific runtime interpreter.

6. Preserve a small public API.

   Existing public names such as =FreeBoson=, =Bc=, =FreeFermion=, =EtaXi=,
   =product=, and =boundary= should remain stable.  Their implementation can
   become generated aliases or thin wrappers.

* Target Architecture

** Lisp Layer

The Lisp DSL owns authoring and UX.

It must provide:

- Parameterized preset templates:

  #+begin_example
  (define-cft-preset (free-boson :dimension d) ...)
  (instantiate-preset free-boson :dimension 26 :theory-id 5)
  #+end_example

- Macroexpansion-time parsing and validation.
- Stable explicit theory IDs.
- Generated field inserters with docstrings and exports.
- Derived basis and infinity data from weights when valid.
- Explicit override forms for non-primary or branch-global fields.
- Zero-mode measure declarations.
- A single scalar grammar reused by Wick expressions and metadata.
- A single expression grammar for chiral and bulk Wick rules.

The macro output is descriptor data, not generated hand-written logic.

** Descriptor Layer

The descriptor becomes the complete bulk-theory contract.

It should contain:

- Theory identity: stable id, name, hash, descriptor ABI version.
- Parameters: dimension, scalar parameters, modular parameters, group data.
- Surfaces: sphere, disk, torus, and coordinate model metadata.
- Fields: insertion shape, statistics, labels, weights, quantum numbers,
  zero-mode participation, infinity behavior, basis behavior.
- Wick rules: scalar monomials, coordinate kernels, tensors, actions,
  residuals, and index constraints.
- Zero-mode measures: declarative residual measure programs.
- Basis rules: oscillator families, seeds, derived quantum deltas, render
  metadata.
- ABI metadata: generated field inserter names and stable field ids.
- Reserved future slots: boundary rules, compact-boson winding/lattice data,
  current-algebra structure data, OPE-specific services.

** Zig Compile-Time Lowering

Zig receives descriptors and builds static storage:

- =wick.Rule= arrays.
- =InfinityTermProgram= arrays per Wick term/orientation.
- =BasisRule= storage for basis enumeration.
- =ZeroModeProgram= storage for residual measures.
- Generated context and field builders.
- Generated ABI dispatch tables.

Each program should be a compact array of small tagged operations, with counts
and offsets known at comptime.

** Runtime

Runtime remains procedural:

- The Wick walk enumerates pairings.
- Pair terms replay static programs.
- Zero-mode residuals replay static measure programs.
- Basis generation traverses static oscillator/seed families.
- Result sinks receive compact streamed factors.

No runtime branch should inspect Lisp forms, descriptor syntax, or per-theory
semantic names.

* Priority 1: Scalar Monomials Everywhere

** Problem

The runtime scalar event stream already understands monomial scalars, but the
descriptor input still accepts only a small set of scalar cases.  This makes
valid worldsheet expressions fail in the DSL.

** Data Model

Replace descriptor scalar variants with:

#+begin_example
ScalarMonomial:
  rational: Rational
  imaginary_power: u2
  atom: optional ParameterId
  atom_power: i8
#+end_example

This supports products like:

#+begin_example
(* -1/2 alpha-prime)
(* -1/2 i alpha-prime)
(* 1/4 alpha-prime)
(* -3/2 i g)
#+end_example

Sums remain represented as multiple Wick terms.

** Tasks

2. Update Lisp =parse-scalar-factor= to emit monomials directly.
3. Reuse the same scalar-product parser for Wick expressions and metadata.
4. Update descriptor lowering to =declare.scalars= values.
5. Bump descriptor ABI version.
6. Regenerate fixtures.
7. Add parser and lowering tests.

** Acceptance

- The free-boson =1/4 alpha-prime= weight expression is accepted without a
  special case.
- No scalar expression tree is introduced.
- Existing generated fixtures produce identical correlator output.

** Status

Complete as of 2026-06-12.  Wick and zero-mode scalar factors now have a

* Priority 3: Lisp Macro Compiler Upgrade

** Problem

=define-cft-preset= currently uses little macro power.  It registers a runtime
builder, and many errors arise later without useful file/line context.

** Macro Responsibilities

The macro should:

- Parse forms at macroexpansion time.
- Validate field references, labels, scalar syntax, surfaces, and zero-mode
  references.
- Generate one runtime inserter per field.
- Generate exports for public field inserters and runtime constructors.
- Attach source locations to descriptor records where SBCL exposes them.
- Derive defaults for weights, basis, infinity, and residuals when rules are
  unambiguous.
- Expand parameterized templates into instantiable descriptors.

** UX Target

Users should write:

#+begin_example
(define-cft-preset (free-boson :dimension d)
  (:theory-id 5)
  (parameter alpha-prime "alpha-prime" :scalar-parameter)
  (surface sphere :sphere :rational)
  (target-vector mu :dimension d)
  (bulk-field X ((mu :vector-index)) :bosonic :weight 0 :anti-weight 0)
  (chiral-field dX ((mu :vector-index)) :bosonic :weight 1)
  ...)
#+end_example

The macro should generate:

- Descriptor data.
- Runtime field inserters.
- Exported symbols.
- Stable ids.
- Source-aware validation messages.

** Tasks

2. Make the macro call the parser during expansion.

4. Generate runtime inserters from descriptor field metadata.

6. Add parameterized preset template support.

** Acceptance

* Priority 4: Descriptor-Driven Basis And Dimension Parameters

** Problem

Basis generation is the largest remaining hardcoded layer.  The generated ABI
uses a handwritten theory-id switch and hardcoded dimension =10=.  Adding a new
free-field theory still requires Zig basis code.

** Data Model

Add descriptor basis records:

#+begin_example
BasisRule:
  quantum_schema
  oscillators: []OscillatorSpec
  seeds: []SeedSpec
  render_atoms: []RenderAtom

OscillatorSpec:
  field
  base_weight_ticks
  derivative_step_ticks
  statistics
  multiplicity_source
  quantum_delta
  component_source

SeedSpec:
  field
  fixed_weight_ticks
  quantum_delta
  fermionic_subset
#+end_example

Multiplicities can reference parameters, especially dimension.

** Derivation Rules

The Lisp macro may derive defaults:

- Chiral field with positive weight -> oscillator family.
- Chiral fermion with half-integer mode spacing -> NS-style oscillator band.
- Field with nonpositive ghost-like seed weight -> seed family when declared as
  a seed source.
- Vector-index label -> multiplicity from dimension or index sort.
- Quantum-number declarations -> quantum deltas.

Derived data must be emitted explicitly in the descriptor so it can be audited.

** Tasks

1. Add descriptor parameter records.
2. Add descriptor basis records.
3. Lower basis records to existing =basis_generation= tables at comptime.
4. Generate ABI basis dispatch from generated fixtures.
5. Remove hardcoded dimension =10= from =generated_abi.zig=.
6. Add parity tests against existing handwritten basis generators.

** Acceptance

- Free fermion, eta-xi, bc, and free-boson basis generation run from descriptor

- Adding a new first-order system with standard oscillator bands requires no new

- Product basis generation still composes through the existing generic product

* Priority 5: General Zero-Mode Measure Builder

** Problem

Zero modes are currently selected from a small closed set.  That is too narrow
for worldsheet applications.  We need a DSL that declares residual measures,
and a Zig lowering path that compiles them into bounded procedures.

** Target Concept

A zero-mode rule is a measure program:

#+begin_example
ZeroModeMeasure:
  surface
  selector: ResidualSelector
  saturation: SaturationRule
  local_data: LocalDataRule
  transform: TransformRule
  emission: EmissionProgram
  normalization: ScalarMonomial or parameter reference
#+end_example

This is still not a runtime interpreter.  Each field is compact descriptor data
lowered into static Zig arrays.

** Residual Selection

Selectors describe which residual fields the measure can consume:

#+begin_example
ResidualSelector:
  accepted_fields: []FieldId
  exact_count: CountExpr
  optional_labels: []LabelConstraint
  allow_derivatives: bool
  allow_infinity: InfinityPolicy
#+end_example

Examples:

- eta-xi constant mode: one =xi= residual, no jet polynomial.
- bc sphere top form: three =c= residuals, jet-aware top-form polynomial.
- free boson momentum conservation: all plane-wave residual momenta plus
  optional profile residuals.
- future first-order systems: =N= residual gamma-like zero modes or beta-like
  moduli insertions, depending on surface and bundle data.

** Saturation Rules

Support a small set of mathematical saturation forms:

1. =grassmann_count=

   Consumes exactly =N= residuals from selected fermionic fields and emits a
   measure factor.  This covers constant fermions and simple eta-xi zero modes.

2. =grassmann_top_form=

   Consumes exactly =N= residual jets and emits the determinant/Vandermonde-like
   top-form polynomial specified by the measure.  The current bc sphere case is
   =N=3.

3. =linear_conservation=

   Accumulates labels such as momenta and emits a conservation delta with
   normalization data.  This covers free-boson zero modes.

4. =residual_functional=

   Reserved for profile/function residuals where the measure emits a compact
   symbolic factor or action.  This should stay bounded and explicit; it is not
   arbitrary Lisp evaluation.

** Emission Programs

The measure emission should be data:

#+begin_example
EmissionProgram:
  scalar_ops
  coordinate_ops
  tensor_ops
  zero_mode_factor_ops
  action_ops
#+end_example

For top forms, coordinate emission should include determinant-style recipes:

#+begin_example
TopFormKernel:
  basis_functions: [1, z, z^2, ...] or named finite basis
  jet_action: derivative order acts on basis functions
  antisymmetry: determinant
#+end_example

This is more general than selecting =bc_top_form=.  It can express the current
=<c c c>= sphere top form, descendant limits at infinity, and future finite
rank Grassmann top forms.

** Infinity And Local Coordinates

Zero-mode measures must explicitly state how infinity is handled:

- reject infinity;
- primary BPZ limit;
- top-form local-coordinate limit;
- branch-global exponential/momentum behavior;
- custom named transform, only if the descriptor has a corresponding lowering
  implementation.

The current one-=c(infinity)= top-form behavior becomes a specialization of the
top-form local-coordinate transform, not an ad hoc sink branch.

** Tasks

1. Introduce =ZeroModeMeasure= descriptor records.
2. Keep old Lisp forms as aliases while authored presets move to explicit
   measure syntax:

   #+begin_example
   (zero-mode (grassmann-count :field xi))
   (zero-mode (grassmann-top-form :field c))
   (zero-mode (linear-conservation :field expX
                :normalization (pow (* 2 pi) 10)))
   #+end_example

   These expand into explicit measure records.  Special named constants such as
   a two-pi power are not part of the DSL; they are scalar expressions.

3. Add Zig =ZeroModeProgram= storage and lowering.
4. Port eta-xi constant mode to =grassmann_count=.
5. Port bc sphere top form to =grassmann_top_form=.
6. Port free-boson momentum conservation to =linear_conservation=.
7. Move infinity top-form handling out of the special sink branch and into the
   top-form program when practical.
8. Add tests for count, derivative jets, infinity handling, and rejection
   messages.

** Acceptance

- New zero-mode measures can be declared without adding a Zig enum variant.
- Existing zero-mode behavior is reproduced exactly.
- Top-form rank is data-driven, with a clear maximum and explicit determinant
  lowering.
- Unsupported measure forms fail at descriptor validation with a precise error.
