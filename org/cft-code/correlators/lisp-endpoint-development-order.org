#+title: Lisp Endpoint Development Order

* Purpose

This node gives the implementation order for the Lisp-driven CFT endpoint.  It
refines [[id:20260608T180000.000000][Lisp CFT DSL Specification]],
[[id:20260607T170000.000000][CFT API Leakage Handoff]], and
[[id:20260607T140000.000000][Generated Correlator Implementation Plan]].

The main correction is that Zig does not get a second user DSL.  Lisp owns the
surface language, macros, inference, symbolic operator data, and generated
source emission.  Zig owns a compact generated descriptor schema and the
comptime conversion of that descriptor into fast correlator internals.

The target pipeline is:

#+begin_src text
Common Lisp surface forms
  -> Common Lisp normalized physics IR
  -> generated Zig descriptor source
  -> Zig comptime lowering
  -> compact runtime tables
  -> streaming correlator
  -> stable result events
  -> Common Lisp expression objects
#+end_src

The descriptor emitted into Zig is intentionally boring.  It is not a syntax
that users write.  It is the wire contract between Lisp and Zig.  Generated
Zig may be repetitive, verbose, and unattractive as hand-written source.  That
is acceptable when the Lisp-Zig boundary is clear, Zig comptime lowering is
deterministic, and the resulting runtime data structures remain lean and fast.

* Non-Negotiable Invariants

These rules govern every step below.

- Edits to implementation code must be made in the corresponding =org= node
  and then tangled to =src=.  The =src= tree is generated output.
- The public root CFT API remains small.  Runtime internals stay hidden from
  user code and from the future Lisp endpoint.
- The generic Lisp emitter and generic Zig lowerer do not dispatch on CFT
  names.  Names such as =eta-xi=, =SO32=, =spin-field=, =rns-flat=, and
  =free-boson= may appear in presets, docs, tests, and symbol tables, but not in
  generic lowering logic.
- Symbolic expressions must be streamed.  Do not materialize large expression
  trees in Zig by default.
- The correlator runtime remains procedural and data-oriented: compact arrays,
  table lookup, bounded branch state, and no large intermediate expressions.
- Generated Zig source is optimized for unambiguous machine generation,
  comptime validation, and efficient runtime lowering, not for hand-authored
  elegance.
- Tests are added only when they pin a concrete invariant: public leakage,
  descriptor validation, byte-equivalent lowering, name preservation, result
  event shape, or benchmark behavior.
- Benchmark gates remain strict after meaningful runtime or API changes.

* Current State

The current runtime is a usable backend foundation.

- =shared.streamCorrelator= takes opaque configs and operator lists and drives
  the generic Wick traversal.
- Pair lookup, branch accumulation, fermion signs, and zero-mode base cases are
  already private runtime machinery.
- =LocalOperator=, =OperatorList=, and correlator config handles are opaque.
- Product and boundary composition already merge private table slices.

The current declaration layer is not yet a clean Lisp endpoint.

- Presets still handwrite family enums, operator namespaces, Wick helper
  functions, zero-mode storage, and config assembly.
- =shared.declare.Spec= is too close to existing runtime tables.  It expects
  compact kind ids, fixed label tags, prebuilt =wick.Expr= values, and
  backend-flavored zero-mode payloads.
- =Local.coord("z")=, =Local.index("mu")=, and similar calls discard the names,
  so Zig cannot return Lisp-readable expressions with the user's symbols.
- Weight and quantum-number rules are not first-class.  This blocks correct
  metadata for =expX=, whose weight depends on =k^2=.
- Zero-mode variants are still backend-named in places.  That is acceptable
  internally for now, but not at the descriptor or Lisp boundary.

* Development Order

** Descriptor Schema

This schema is the first real Lisp-Zig contract.  Lisp emits it.  Zig validates
and lowers it.  Users do not write it.

All ids in the generated descriptor are dense zero-based integers unless the
field says otherwise.  Names are kept for diagnostics, ABI symbol metadata, and
result rendering.  Lowering must never identify a field by comparing its name to
a known CFT field name.

** Generated Artifact Lifecycle

The Lisp REPL compiles generated Zig theories through an explicit lifecycle.

1. Lisp normalizes the theory to IR.
2. Lisp computes a content hash over:
   - normalized IR;
   - descriptor ABI version;
   - Zig lowerer ABI version;
   - target triple;
   - optimize mode.
3. Lisp writes generated Zig into a cache directory keyed by that hash.
4. Lisp invokes =zig build-lib= or a small generated build file to produce a
   shared library.
5. Lisp loads the shared library through CFFI.
6. Lisp calls an exported ABI-version function before any other entrypoint.
7. If the version or hash does not match, Lisp unloads or ignores the library
   and rebuilds.

Development fixtures may be tracked in the repository.  REPL-generated
artifacts are cache artifacts and should not be tracked.

Required generated file layout:

#+begin_src text :tangle no
.cache/string-code/cft/<hash>/
  theory.zig
  build.zig
  libtheory.so
  manifest.sexp
#+end_src

The manifest records:

- normalized IR hash;
- descriptor ABI version;
- Zig lowerer ABI version;
- Zig version string;
- target triple;
- optimize mode;
- exported field/surface ids.

Canonical generation rules:

- descriptor arrays are emitted in id order;
- generated ids are dense and deterministic;
- map-like Lisp inputs are sorted by normalized symbol name before emission;
- generated Zig whitespace is stable but not optimized for beauty;
- comments in generated Zig are optional and should be sparse;
- content hash is computed from normalized IR, not from pretty source text.

** Runtime Symbol Interning

Symbol interning is per calculation context.  Descriptor-level ids are fixed
per generated theory.  Runtime symbol ids are local to one calculation context.

Intern key:

#+begin_src text :tangle no
(role, name, domain)
#+end_src

Rules:

- interning the same key twice in one context returns the same id;
- interning the same name with different roles returns different ids;
- a frozen operator list keeps using the context symbol table that created it;
- symbols live until the calculation context is destroyed;
- contexts are independent and may reuse numeric ids;
- Lisp owns the input string memory only for the duration of the ABI call;
- Zig copies interned names into context-owned memory.

This gives the expected behavior:

#+begin_src text :tangle no
coord("z")  -> id 1
coord("z")  -> id 1
index("z")  -> id 2
coord("w")  -> id 3
#+end_src

** Stable Result Event Payloads

Result events are streamed as tagged payloads.  The event tag is stable across
generated theories with the same ABI version.

Required event shape:

#+begin_src zig :tangle no
pub const ResultEvent = union(enum) {
    sum_start,
    sum_end,
    term_start: TermInfo,
    term_end,
    branch_sign: i8,
    scalar: ScalarEvent,
    coordinate: CoordinateEvent,
    tensor: TensorEvent,
    action: ActionEvent,
    zero_mode: ZeroModeEvent,
    residual_operator: ResidualOperatorEvent,
    base_case_end,
};
#+end_src

Minimum payload requirements:

- scalar event: rational value, parameter ref, or named scalar atom;
- coordinate event: kernel kind, coordinate ids, power, derivative action;
- tensor event: tensor kind, label ids, optional representation/domain ref;
- action event: action kind and affected runtime symbols;
- zero-mode event: generic zero-mode emission kind and payload refs;
- residual operator event: original operator occurrence or generated operator
  body id;
- term start: pair occurrence ids and term ordinal.

Event payloads use descriptor ids for theory-level entities and runtime symbol
ids for calculation variables.  Lisp resolves both into its expression format.

If a Lisp callback fails while consuming events, the callback returns an error
status.  Zig stops streaming and returns that status to the ABI caller without
continuing traversal.

** REPL Result Modes

The REPL must be able to inspect correlator results without changing the
runtime architecture.  Zig exposes a stream; Lisp decides whether to ignore,
count, collect, print, or convert that stream.

There are three result modes.

1. Void/count mode.

   This is the benchmark path.  Zig streams events to a sink that discards
   payloads or counts primitive terms, zero-mode factors, residual operators,
   and base cases.  It is used for speed gates and should remain the default
   internal performance path.

2. Lisp callback stream mode.

   This is the general REPL and library path.  Zig calls a Lisp-provided CFFI
   callback for every result event.  Lisp can print, simplify, count, collect,
   or abort.  Zig does not know the Lisp expression representation.

3. Lisp collector mode.

   This is a Lisp helper built on top of callback stream mode.  It collects
   events into a bounded Lisp-side expression object so ordinary REPL use can
   return a value.  The collector is not a Zig expression materializer.

The user-facing Lisp API should separate these modes:

#+begin_src lisp :tangle no
(corr surface operator-list)              ; returns a Lisp expression object, bounded
(corr-stream surface operator-list sink)  ; calls SINK for streamed events
(corr-count surface operator-list)        ; returns counts only
#+end_src

Collector limits:

- maximum terms;
- maximum factors per term;
- maximum residual operators;
- maximum zero-mode factors;
- maximum output bytes for printed fallback;
- overflow policy.

Default overflow policy:

- stop collection;
- keep counts accumulated so far;
- return a Lisp object marked =:truncated=;
- leave the Zig traversal stopped through callback error/abort status.

This makes the REPL usable while preserving the rule that Zig does not allocate
large symbolic expressions by default.

** ABI Ownership And Concurrency

Generated ABI functions must obey these rules:

- Every opaque pointer has exactly one destroy function.
- Contexts are not thread-safe unless explicitly marked otherwise.
- Correlator execution is reentrant across distinct contexts.
- A frozen operator list belongs to the context that created it.
- Passing objects across contexts is an error.
- Lisp may call into different generated theory libraries independently.
- Zig never stores pointers to Lisp-owned buffers after an ABI call returns.
- Lisp callbacks receive only POD event payloads and opaque user data.
- ABI errors are returned as small status codes with optional context-local
  error strings.
- The first ABI call after loading must check descriptor ABI version and theory
  hash.

Minimum exported ABI:

#+begin_src text :tangle no
theory_abi_version() -> u32
theory_hash(out_ptr, out_len) -> status
context_create(out_context) -> status
context_destroy(context) -> void
intern_symbol(context, role, domain, ptr, len, out_id) -> status
field_insert(context, field_id, insertion_payload, labels, out_operator) -> status
normal_order(context, operators, count, out_operator) -> status
operator_list_freeze(context, operators, count, out_list) -> status
correlator_run(context, surface_id, list, callback, user_data) -> status
correlator_count(context, surface_id, list, out_counts) -> status
last_error(context, out_ptr, out_len) -> status
#+end_src

** Phase 8: Add Generated ABI Wrappers

Goal: make a generated theory callable from the Lisp REPL at runtime.

Edit targets:

- descriptor lowerer org node;
- generated free-fermion Zig fixture;
- Common Lisp package.

Generated Zig module exports:

- create calculation context;
- destroy calculation context;
- intern symbol name with role;
- create field insertion by field id;
- create normal-ordered local operator group;
- freeze an operator list;
- select surface or config id;
- run correlator;
- stream result events;
- release result/context resources.

ABI design:

- use stable integer ids for fields, surfaces, roles, and event tags;
- pass strings as pointer plus length;
- pass errors as small tagged status codes;
- do not expose =kernel.Call.LocalOp=, =MultiOp=, =PairLookupEntry=,
  branch state, residual masks, or =emitWick*= names;
- keep ownership explicit: Lisp owns input strings, Zig owns context-local
  interned copies, Lisp consumes streamed output before context destruction.
- contexts are thread-confined by default;
- callback failure aborts traversal and returns a status code to Lisp;
- objects created in one context cannot be passed to another context.

Common Lisp side:

- use CFFI;
- wrap raw pointers in Lisp objects;
- expose theory context, operator values, normal ordering, streaming correlator
  calls, count-only correlator calls, and bounded REPL collection;
- keep user operator data first-class and reusable.

Acceptance:

- Lisp can create =psi(mu,z)= and =psi(nu,w)= as stored operator data.
- Lisp can call the generated free-fermion correlator.
- Lisp receives structured result events and converts them into a Lisp
  expression object.
- Zig never returns a materialized full expression tree by default.
- The ABI version and generated theory hash are checked before correlator calls.
- The REPL can request a collected Lisp result, a streamed callback, or counts
  only.
- Collector overflow returns a marked Lisp value rather than silently dropping
  terms.

* Implementation Notes

The first Common Lisp package should be deliberately small.  The goal is not to
ship a full language before the Zig descriptor lowerer exists.  The first Lisp
program should prove only this loop:

#+begin_src text
compact free-fermion Lisp declaration
  -> normalized Lisp IR
  -> generated Zig descriptor
  -> Zig compile
  -> ABI call
  -> streamed result
  -> Lisp expression
#+end_src

Once that loop works, add eta-xi and free boson.  Do not start with the full
RNS language, spin fields, or SO(32).  Those are design pressure tests for the
generic vocabulary, not the first endpoint.

The current handwritten presets are migration fixtures.  They should be used
to verify byte-equivalence and benchmark stability, then progressively reduced
to generated descriptors plus small compatibility wrappers.

The final result should make the user-side work look like physics:

#+begin_src lisp :tangle no
(wick (psi mu z) (psi nu w)
  (/ (eta mu nu) (- z w)))
#+end_src

while the generated Zig remains explicit data:

#+begin_src zig :tangle no
.{
    .left = field_id.psi,
    .right = field_id.psi,
    .terms = &.{
        .{
            .tensors = &.{ .{ .metric = .{ .left_label = 0, .right_label = 0 } } },
            .coordinates = &.{ .{ .rational_pole = .{ .power = -1 } } },
        },
    },
}
#+end_src

That separation is the point of the architecture.
